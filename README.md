# 모아 — Instagram 이미지 일정 정리

별도 프로젝트의 첫 실행 가능한 버전입니다. 기존 Reelbox 코드·토큰을 사용하지 않습니다.

## 실행

Node.js 24 이상이 필요합니다. 처음 받은 소스에서는 `npm ci`로 Google 공식 인증 라이브러리를 설치합니다.

```powershell
cd 'D:\AI_SW_2026팀플\instagram-calendar'
npm start
```

브라우저에서 http://127.0.0.1:3080 접속. 또는 `start.ps1` 실행.

CMD에서는 드라이브 이동을 포함해 `cd /d "D:\AI_SW_2026팀플\instagram-calendar"` 후 `npm start`를 실행합니다.
실행 직후와 이후 60초마다 콘솔에 서버 상태, 메모리, SQLite 연결, 분석·수집 현황,
최근 요청 건수·응답 코드·처리 시간과 변경 사항을 요약합니다. 요청이 없어도 출력하며,
HTTP 오류와 응답 중단은 즉시 알립니다. 인증정보·요청 본문·일정 내용·URL 쿼리는 출력하지 않습니다.
이 요약은 실행 중인 로컬 서버 기준이며 Vercel이나 외부 API의 정상 작동을 보증하지 않습니다.
코드 업데이트 후에는 기존 서버를 Ctrl+C로 종료하고 다시 시작해야 적용됩니다.

`.env.local`에 승인받은 OpenAI 키가 저장됩니다. 키를 브라우저, Git, 채팅에 복사하지 않습니다.
선택 설정은 `.env.example` 참고. 기본 모델은 `gpt-5.4-mini`, 하루 분석 요청 상한은 20회입니다.

## 사용 순서

0. 회원가입 후 로그인합니다. 첫 가입 계정은 관리자이며 기존 로컬 기록·Google 연결·구독을 이어받습니다. 이후 가입 계정은 별도 사용자로 시작합니다.
1. Instagram 게시물 이미지 1~3장(PNG/JPG/WebP, 각 3MB 이하)을 업로드합니다.
2. 선택적으로 캡션, 계정, 게시일, 원본 주소를 입력합니다. 주소만으로 자동 수집하지 않습니다.
3. 분석하면 행사·신청·예약 일정을 따로 추출합니다. 이미지와 캡션은 OpenAI API로 전송됩니다.
4. 원문과 비교하고 날짜·시간대·장소를 수정합니다. 불필요한 후보는 제외합니다.
5. 확인란을 선택하고 저장하면 `.ics` 파일을 받을 수 있습니다.

연도가 누락된 날짜는 임의 확정하지 않습니다. 시간대 미표기도 확인이 필요합니다.
현재 검토 화면은 한국(Asia/Seoul)과 UTC를 지원합니다. 종료일은 마지막 날을 포함합니다.
시간을 비우면 종일 일정입니다. 시간이 있는 일정의 종료 시간을 추측하지 않습니다.
이미 지난 날짜는 화면에서 경고합니다. AI 추출은 틀릴 수 있으므로 원문을 확인해야 합니다.

Google OAuth 연결·토큰 갱신·전용 캘린더 생성·검토한 일정 등록,
Meta Business Discovery 조회·사용자별 구독 관리·60분 주기 수집·중복 분석 방지,
회원가입/로그인/로그아웃·세션·사용자별 업로드/검토/Google 연결 격리·신규 계정 초기 역방향 수집.

단일 사용자 흐름의 실제 Meta 수집·OpenAI 분석·Google 일정 등록은 검증했습니다. 회원별 권한 분리와 초기 수집은 모의 API 및 로컬 화면으로 검증했습니다.
미구현: 영상 분석, 이메일 인증/비밀번호 복구, 행사 취소/삭제 자동 반영, 등록된 일정 자동 수정, 외부 접속.
`.ics` 반복 가져오기 시 캘린더 서비스에 따라 중복될 수 있습니다.
Google 직접 등록은 분석 ID에 연결된 고정 이벤트 ID로 중복을 방지합니다. 등록 후 로컬 결과를 수정하면 덮어쓰기를 차단합니다.
현재는 한 PC의 여러 회원·단일 서버 프로세스용입니다. 루프백 HTTP에서 실행하며 외부 배포용 HTTPS·이메일 인증·계정 복구·운영 구성을 아직 제공하지 않습니다.

## 비용과 데이터

- 동일 이미지·캡션·메타데이터·모델·프롬프트 버전은 성공한 결과를 재사용합니다. 수동 업로드 캐시는 회원별이며 공개 Instagram 수집 결과만 구독자끼리 공유합니다.
- 입력 변경 시 새 분석 요청이 됩니다. 자동 재시도하지 않습니다.
- 동시에 한 건만 처리합니다. 하루 상한은 서울 날짜 기준이며 실패도 포함합니다.
- 요청당 출력은 6,000토큰 이하. 상한은 비용 금액 한도가 아니며 OpenAI 결제와 별개입니다.
- 토큰 사용량은 분석 기록의 `usage`에 저장됩니다. 중단 요청의 실제 사용량은 알 수 없습니다.
- `store:false`로 요청합니다. 이는 제공자의 모든 로그/보관 정책을 비활성화한다는 뜻은 아닙니다.
- 이미지 원본은 메모리에서만 처리하고 앱 DB에 저장하지 않습니다. 캡션·메타데이터·분석·수정 결과는 `data/events.sqlite`에 저장됩니다.
- `.env*`, `data/`, `.key-setup/`는 Git 제외. `data/test-poster.png`는 개발용 합성 포스터입니다.
- 백업할 때 서버를 종료한 뒤 `data` 폴더를 복사합니다. 키 파일은 별도로 안전하게 관리합니다.
- 요청 중 서버를 재시작하면 해당 작업은 중단 상태가 됩니다. 재분석은 수동으로 실행합니다.
- 자동 수집 작업은 재시작 시 대기 상태로 복원합니다. 계정별 켜짐/꺼짐과 다음 조회 시간도 DB에 보관합니다.
- 연동 비밀정보는 `data/integrations.enc`에 AES-256-GCM으로 저장합니다. `data/integration.key`도 함께 백업해야 합니다.
  같은 PC 계정이 두 파일을 모두 읽을 수 있으면 복호화할 수 있으므로 OS 계정과 백업의 접근 권한도 관리해야 합니다.

접근 실패는 개인 계정이라는 증거가 아닙니다. 프로페셔널 대상도 권한·연결·앱 접근 수준 문제로 실패할 수 있습니다.

3. 관찰할 공개 계정을 추가. Business Discovery 실제 조회 성공 후 등록됩니다.
4. 계정별 `지금 수집`으로 시험한 후 `자동 수집 켜기` 선택.

자동 수집은 서버가 실행되는 동안 60분 주기입니다. 서비스에 처음 등록되는 계정은 최신 피드부터 과거 방향으로 페이지를 넘기며 수집합니다.
한 게시물에 명시된 일정이 모두 지난 날짜이고 행사(event)가 하나 이상 있을 때 초기 수집을 종료합니다. 오늘 일정·미래 일정·불명확한 날짜·경고가 있는 결과·일정 없는 글·신청 일정만 있는 글은 종료 근거로 사용하지 않습니다.
과거와 미래 일정이 섞이면 계속 수집합니다. API 페이지의 타임스탬프를 내림차순으로 정렬하며, ‘과거 행사에서 종료’ 자체는 과거 게시물에 미래 행사가 없음을 보장하는 방식은 아닙니다.
회당 최대 5개 게시물을 처리하고 커서·남은 큐를 SQLite에 저장합니다. 일일 20회 분석 상한이나 재시작 이후 이어갑니다. 초기 수집 1,000개 상한은 완료로 표시하지 않고 수동 확인 필요 상태로 멈춥니다.
이미 등록된 계정은 기존 결과를 재사용합니다. 초기 수집 완료 후 최신 확인은 최근 30개 또는 지난 행사 지점까지입니다.
기존 시험 계정은 수집 이력을 유지하며 최초부터 다시 분석하지 않습니다.
자동 수집은 사진 최대 20장을 한 요청으로 분석합니다(수동 업로드는 3장 제한 유지). 영상 포함·이미지 누락·20장 초과는 수동 확인 대상으로 기록하고 종료 근거로 사용하지 않습니다. 실패는 최대 3회 시도하며 예산/동시 처리 제한은 시도 횟수를 소모하지 않습니다.
각 사용자는 구독 추가·취소·일시정지·재개를 할 수 있습니다(최대 20개). 한 명이라도 활성 구독자이면 공유 수집은 계속되지만 다른 사람의 구독 설정은 변경하지 않습니다.
회원별 Google 토큰·전용 캘린더·검토 결과를 분리합니다. Meta 서비스 연결과 공통 Google OAuth 클라이언트 설정은 관리자만 변경할 수 있습니다.
회원 비밀번호는 무작위 salt와 비동기 scrypt로 저장합니다. 세션은 무작위 토큰의 해시만 DB에 보관하며 HttpOnly/SameSite=Lax 쿠키, 7일 만료, 로그아웃 폐기, 로그인 시도 제한을 적용합니다.
참고: https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback
서로 다른 게시물의 같은 행사인지 의미를 비교하는 중복 감지는 미구현입니다.
게시물 삭제·취소를 자동으로 캘린더 삭제로 해석하지 않습니다. 변경된 추출 결과는 새 검토가 필요합니다.

### Git 기반 배포
